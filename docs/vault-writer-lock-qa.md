# Exclusión de escritores portable en Linux

Prerrequisito del futuro wizard, no wizard implementado. Linux portable serializa init/set/setMany/rm, incluidas las rutas CLI set y set-stdin, con una cerradura OS ligada al archivo efectivo de secretos, no al directorio de estado. Dos procesos con distintos PA_STATE_DIR pero el mismo PA_SECRETS_FILE comparten la exclusión. La cola previa dentro de un proceso se mantiene. Espera acotada5s; sin flock falla cerrado. El kernel libera la cerradura al morir el proceso; el archivo writer.lock nunca se borra para evitar carreras entre waiters.

Se valida ruta sin symlinks, directorio privado/propietario actual, archivo regular privado con un enlace (no hardlinks/symlinks), y que el lock siga siendo el mismo inode bajo la propiedad. El archivo externo PA_SECRETS_FILE se valida igual; no se asume seguro por estar fuera del estado. Una carpeta nueva se crea con700; permisos abiertos existentes se rechazan sin chmod silencioso. ensureDirs también usa700 para carpetas nuevas para no crear una instalación que rechace su propio almacén. Windows conserva DPAPI/portable existente: no se afirma un mutex Windows.

La escritura portable pasa de .tmp fijo a temporal único exclusivo600+rename atómico. Si falla el commit, se intenta retirar solo su propio temporal y no el .tmp de otra persona. Una limpieza que falle podría dejar un temporal privado600; no se registra contenido ni se hace limpieza amplia. No modifica archivos reales del usuario en QA.

Límites: exclusión entre escritores de esta versión que cooperan con la cerradura, no frente a editores externos, versiones viejas, root o procesos hostiles del mismo UID. No se promete transacción universal ni verificación de semántica de cada filesystem remoto. Los lectores y la caché de valores conservan su comportamiento anterior; este PR no promete que una lectura ya cacheada vea una rotación hecha por otro proceso. El futuro wizard deberá obtener snapshot efectivo fresco y confirmar el commit bajo esta exclusión, sin copiar overrides del entorno al archivo. No usa openDaemonControl, no reclama metadata stale ni publica READY/stopped.

QA Linux: dos procesos/operaciones sobre mismo archivo excluidos, archivos distintos no bloqueados, directorio abierto rechazado sin modificarlo, symlink/hardlink/archivo abierto/lock symlink rechazados, doce procesos con cuatro tipos de operación en archivo externo compartido conservan todos los campos esperados; crash de fixture propio libera lock sin borrarlo. Fallo inyectado de rename conserva el archivo anterior y no toca un .tmp ajeno. Tests portable/env/delete anteriores siguen verdes. No QA nativa Windows, no cuenta/sesión/vault real de Nico, cero red/modelos. Fresh suite completa pendiente al publicar.
