# Propiedad sin reclamación para el futuro wizard

Primitiva Linux independiente del wizard todavía sin cablear. inspectSetupOwnership hace revisión solo lectura, también si falta estado: no crea directorios/lock, no sondea PID ni red, no usa assertNotRunning. Rechaza agent.pid, agent.pid.stale y cualquier READY/socket/temporal/control desconocido sin borrarlos ni interpretarlos como permiso. No se reclama una instancia legacy por un timeout. Un daemon legacy que no coopera con flock sigue siendo un límite: toda evidencia ambigua obliga a parar y revisar.

Tras esa revisión, acquireSetupOwnership crea estado/control700 si faltan y adquiere el MISMO owner.lock de chat/serve, pero sin llamar openDaemonControl. Revalida evidencia bajo lock y expone assert/release para el futuro wizard. Nunca abre socket, publica READY/stopped ni crea token. La cerradura se retiene por FD y se libera al cerrar o morir el proceso; no se borra su archivo. Las carpetas/lock creados son infraestructura persistente, no un commit de configuración ni prueba de cierre limpio. Cancelar el futuro wizard no podrá prometer que esos artefactos temporales de coordinación no existan; sí debe prometer cero secretos/configuración cambiados antes de confirmar.

Windows falla antes de tocar estado. Un archivo de lock persistente y nombres de pruebas finales conocidos pueden quedar tras cierre; no se usan como evidencia de limpieza ni de autoridad, solo se valida su tipo/propietario/permisos. Si cambia evidencia durante el wizard, assert falla cerrado. No protege de root ni de un proceso hostil del mismo UID ni de versiones antiguas que ignoran el protocolo.
